1. ENDPOINTS
---------------------------------------------------------------------------

  Every route: @auth_required(dashboard="informal_business"), a rate
  limit, a marshmallow schema with unknown=RAISE, and every query scoped
  to current_user(). Not found and "not yours" are the same 404.

  --- The entry, as every endpoint returns it ---------------------------

    entry = {
      id:                 uuid
      kind:               "customer_debt" | "supplier_debt"
      source:             "trader"            ("order" later: seam c)
      customer:           {id, name, phone} | null     (customer_debt only)
      supplier_name:      string | null                (supplier_debt only)
      amount_cents:       int     the amount after any corrections
      paid_cents:         int     sum of payments
      outstanding_cents:  int     amount - paid (0 when cancelled)
      description:        string  "" when none
      given_on:           date
      due_on:             date
      status:             "open" | "paid" | "cancelled"
      created_at:         datetime
    }
    entry_detail = entry + {
      history: [ oldest first, append-only
        {id, type: "given",      on, recorded_at, amount_cents}
        {id, type: "repayment",  on, recorded_at, amount_cents}
        {id, type: "correction", on, recorded_at, reason,
             before: {amount_cents, due_on, description},
             after:  {amount_cents, due_on, description}}
        {id, type: "cancelled",  on, recorded_at, reason}
      ]
    }

  GET /me/credit-book/entries?kind=customer_debt|supplier_debt
    Who:          signed-in trader
    Query:        kind (required), status=open|paid|all (default: open +
                  paid; cancelled entries only show in an entry's history)
    Response 200: {entries: [entry]}  open first by due_on (late first),
                  then paid, newest first. Max 500 (a spaza book is far
                  smaller; paging later if ever needed).
    Errors:       422 VALIDATION_ERROR (bad kind/status)
    Rate limit:   120 per minute

  POST /me/credit-book/entries
    Who:          signed-in trader
    Request:      kind:           "customer_debt" | "supplier_debt", required
                  customer_id:    uuid        } customer_debt: exactly one
                  customer:       {name, phone} } of these two
                    name:         string 1..60 (trimmed)
                    phone:        SA cellphone or null; stored 0XXXXXXXXX
                  supplier_name:  string 1..80, supplier_debt only
                  amount_cents:   int 1..10,000,000 (R100,000)
                  description:    string 0..120, optional
                  due_on:         date, today .. today + 366 days
                  (given_on is always the server's today, not sent)
    Header:       Idempotency-Key (optional; src/shared/idempotency) so a
                  retry after a dropped connection can't add it twice
    Response 201: {entry: entry_detail}
    Errors:       422 VALIDATION_ERROR (field errors), 404 NOT_FOUND
                  (customer_id not the trader's)
    Rate limit:   60 per minute

  GET /me/credit-book/entries/{id}
    Response 200: {entry: entry_detail}
    Errors:       404 NOT_FOUND
    Rate limit:   120 per minute

  POST /me/credit-book/entries/{id}/payments
    Request:      amount_cents: int 1..outstanding_cents
                  paid_on:      date, given_on .. today
    Header:       Idempotency-Key (optional)
    Response 201: {entry: entry_detail}   status becomes "paid" at 0
    Errors:       404 NOT_FOUND, 409 ENTRY_CLOSED (paid or cancelled),
                  422 VALIDATION_ERROR (more than what's left, bad date)
    Rate limit:   60 per minute

  POST /me/credit-book/entries/{id}/corrections
    Request:      amount_cents: int paid_cents..10,000,000 (can't drop
                                below what's already paid back)
                  due_on:       date, given_on .. today + 366
                  description:  string 0..120
                  reason:       string 0..120, optional
    Response 201: {entry: entry_detail}   status recomputed (a correction
                  can settle an entry, or re-open a paid one)
    Errors:       404, 409 ENTRY_CLOSED (cancelled), 422 VALIDATION_ERROR
                  (incl. "nothing was changed")
    Rate limit:   30 per minute

  POST /me/credit-book/entries/{id}/cancel
    Request:      reason: string 0..120, optional
    Response 200: {entry: entry_detail}   status "cancelled"
    Errors:       404, 409 ENTRY_CLOSED (already cancelled),
                  409 HAS_REPAYMENTS (money was paid: correct instead)
    Rate limit:   30 per minute

  GET /me/credit-book/customers?q=
    Query:        q: string 0..60 (empty = everyone)
    Response 200: {customers: [{id, name, phone, owes_cents}]}
                  name starts-with first, then contains; max 50
    Rate limit:   120 per minute (the app searches as you type, 200 ms
                  debounce)

  DELETE /me/credit-book/customers/{id}
    Anonymises: name -> "Deleted customer", phone -> null, soft-deleted.
    Their entries and payments stay (the record must still add up).
    Response 200: {}      Errors: 404
    Rate limit:   30 per minute
    (Not in the app yet: planned for the customer page.)

  GET /me/credit-book/summary
    Response 200: {summary: {
                    customers_owe_cents, customers_owing,
                    due_today_count, due_today_cents, overdue_count,
                    you_owe_suppliers_cents,
                    given_this_month_cents, paid_back_this_month_cents }}
                  (Home tab and Account tile, file 08)
    Rate limit:   120 per minute


2. TABLES (schema "trader", BaseModel: uuid id, created_at, updated_at,
   is_deleted, deleted_at)
---------------------------------------------------------------------------

  credit_customers
    user_id        uuid, not null, index            (the trader)
    name           varchar(60), not null
    phone          varchar(10), null, CHECK ~ '^0[6-8][0-9]{8}$'
    soft delete = anonymise (see DELETE above)
    index (user_id, lower(name))

  credit_entries                      NEVER deleted, not even softly
    user_id        uuid, not null
    kind           varchar(16), CHECK in (customer_debt, supplier_debt)
    source         varchar(8), CHECK in (trader, order), default trader
    customer_id    uuid FK credit_customers, null
    supplier_name  varchar(80), null
      CHECK (kind = 'customer_debt' AND customer_id IS NOT NULL AND supplier_name IS NULL)
         OR (kind = 'supplier_debt' AND supplier_name IS NOT NULL AND customer_id IS NULL)
    amount_cents   bigint, CHECK > 0 AND <= 10000000    (current value)
    description    varchar(120), not null, default ''  (current value)
    given_on       date, not null
    due_on         date, not null, CHECK due_on >= given_on (current value)
    status         varchar(10), CHECK in (open, paid, cancelled)
    index (user_id, kind, status, due_on)

  credit_payments                     NEVER updated or deleted
    entry_id       uuid FK credit_entries, not null, index
    user_id        uuid, not null
    amount_cents   bigint, CHECK > 0
    paid_on        date, not null
    source         varchar(8), CHECK in (trader)   (later: confirmed ones)

  credit_corrections                  NEVER updated or deleted
    entry_id       uuid FK, not null, index
    user_id        uuid, not null
    kind           varchar(12), CHECK in (correction, cancellation)
    before_amount_cents, after_amount_cents   bigint
    before_due_on, after_due_on               date
    before_description, after_description    varchar(120)
    reason         varchar(120), not null, default ''

  History = the entry's "given" line (amount = the first correction's
  before_amount, or the entry's amount if never corrected) + payments +
  corrections, ordered by created_at.

  Migration: 0010_credit_book (please reserve it for me).


3. RULES
---------------------------------------------------------------------------

  - Outstanding = amount - sum(payments). Status is "paid" exactly when
    outstanding hits 0, "open" otherwise, unless cancelled.
  - A payment can't be more than what's left, can't be before the day
    the credit was given, and can't be in the future.
  - Nothing is edited in place from the trader's point of view: a
    correction stores before/after and the entry shows the after. The
    amount can't be corrected below what was already paid back.
  - Cancel is only for an entry with no payments ("entered by mistake").
    With payments, correct the amount instead.
  - Payments and corrections lock the entry row (SELECT ... FOR UPDATE)
    so two taps can't overpay.
  - A new customer is created in the same transaction as their first
    credit sale. Two customers may share a name (two Thandis); the app
    shows existing matches as you type so it's a choice, not an accident.
  - WhatsApp receipts and reminders never touch the server: the app
    opens a wa.me link on the trader's phone (file 10).


4. SECURITY (file 05)
---------------------------------------------------------------------------

  IDOR:      every query filters by user_id = current_user().id, including
             customer_id inside POST /entries. Tests: trader B gets 404 on
             A's entry, payment, correction, cancel, customer delete, and
             A's customers never show in B's search.
  Input:     marshmallow, unknown=RAISE; lengths above; amounts int cents
             1..10,000,000; dates bounded (given_on..today+366); kind and
             status against constants + DB CHECKs.
  Privacy:   a customer is a name the trader chooses (nickname fine) and
             an optional cellphone, only for the trader's own WhatsApp.
             No ID numbers, no addresses. Never shown to suppliers, never
             in the shared record (counts and amounts only). Delete =
             anonymise; amounts stay. "Download my data" would export:
             customers (name, phone), entries, payments, corrections.
  Secrets:   none: no links or tickets in this tool.
  Abuse:     rate limits above (per user).
  Audit:     credit.entry_added      {entry_id, kind, amount_cents}
             credit.payment_recorded {entry_id, payment_id, amount_cents}
             credit.entry_corrected  {entry_id, before/after amount_cents,
                                      due_on changed yes/no}
             credit.entry_cancelled  {entry_id, amount_cents}
             credit.customer_deleted {customer_id}
             Never names, phones, descriptions or reasons.
