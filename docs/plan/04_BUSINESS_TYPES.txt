---------------------------------------------------------------------------
2. THE SHAPE IN CODE
---------------------------------------------------------------------------

    type BusinessType = 'spaza' | 'builder' | 'reseller' | 'food_vendor';
    type ToolKey = 'creditBook' | 'orderStock' | 'jobs' | 'dailyTally' | 'record';

    interface BusinessTypeConfig {
      label: string;                 // sign-up tile
      icon: string;                  // lucide icon name
      orderBookLabel: string;        // "Orders" | "Jobs" | "Sales"
      defaultTools: ToolKey[];       // ON at sign-up; trader can change
      homeCards: HomeCardKey[];      // Home, top to bottom
      templates: TemplateKey[];
      categoriesFirst: Category[];   // Suppliers tab ordering (s4)
    }

    export const BUSINESS_TYPES: Record<BusinessType, BusinessTypeConfig>

    - An unknown type from the server falls back to 'spaza' with a
      warning. It never crashes.
    - The server keeps its own list of allowed keys and rejects
      anything else (422).

  leads with. The trader can add or remove tools any time ("Add a

categories were spaza categories (16 of them, with one catch-all

5. BUILDER TOOLS (PDF p11-p15) -- second priority after spaza
---------------------------------------------------------------------------

  JOB WITH STAGES (p12): client, total, stages (deposit / walls / roof /
    final) each with an amount and a status; "Paid and confirmed R5,000
    of R38,000".
  STAGE PHOTO (p13): camera only, never the gallery; time-stamped; the
    photo's hash is sealed in the stage event.
  SIGN-OFF LINK (p14): sent to the client on WhatsApp; no app needed;
    the client types the cash they paid; one use, 7 days (PLAN 02 s4).
  HOUSE RECORDS (p15): each house's stages as a record the builder can
    share. Stages captured live are "Both" (photo + sign-off); stages
    IMPORTED from WhatsApp are "By you", date unknown, because
    WhatsApp strips the date. We say that on the screen.
