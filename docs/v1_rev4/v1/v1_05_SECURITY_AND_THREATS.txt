THE SENTENCE WE SAY FIRST:

    "A hash chain proves a record wasn't changed after it was sealed.
     It doesn't prove the record was true when entered. The Cash
     Handshake adds a second person who says the same number. Here is
     where even that stops working."

2. THE API: OWASP API SECURITY TOP 10
---------------------------------------------------------------------------

    API1  object-level auth       owner/participant checks on every
                                  order, job, loan and proof read.
                                  Tested with a second account.
    API2  authentication          short-lived JWTs; phone OTP with a
                                  fake provider for the demo; device
                                  key registered at signup
    API3  property-level auth     schemas whitelist writable fields;
                                  status, tier, flags, score and
                                  verified are never client-writable
    API4  resource consumption    rate limits on every write and on
                                  the public share page; batch sizes
                                  capped; paging clamped server-side
    API5  function-level auth     EVERY route pins a role: business,
                                  supplier, or the public share page
    API6  sensitive flows         share-link creation and handshake
                                  uploads rate-limited
    API8  misconfiguration        no debug in the demo build; CORS
                                  locked down
    API9  inventory               one versioned API, /api/v1
    API10 unsafe consumption      every client signature re-verified;
                                  client-sent tiers ignored

THE RULE UNDER ALL OF IT: THE SERVER BELIEVES NOTHING THE PHONE CLAIMS
ABOUT TRUST. The phone sends signed facts. The server decides tiers,
flags, disputes and scores.


3. POPIA
---------------------------------------------------------------------------

    - Each business owns its record and shares only what it chooses,
      for as long as it chooses. It can revoke at any time.
    - Loan Book customers: a name or nickname and amounts, kept inside
      the business's own account. They never appear in a shared record
      or to a supplier.
    - Suppliers see what their own customers do WITH THEM (orders,
      payments), and nothing else without consent.
    - No location tracking. Suppliers set a service area; businesses
      set a suburb. We never read GPS in the background.
    - Account deletion closes share links immediately.


4. DEMO BUILD vs. PRODUCTION (backup slide)
---------------------------------------------------------------------------

    - Bluetooth company ID 0xFFFF (test value)
    - seed data is synthetic and labelled as such
    - demo identities load keys from a dev menu (V1_09 section 6)
    - cleartext HTTP over adb reverse; a temporary public tunnel to
      the checker page process ONLY, never the API (V1_09 section 4)
    - supplier verification is manual (an admin flag)
    - secrets in a local .env, rotated after the event
