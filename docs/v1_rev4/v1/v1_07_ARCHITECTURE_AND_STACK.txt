1. AKAYZA IS SEPARATE. THE RULES THAT KEEP IT SEPARATE
---------------------------------------------------------------------------

    - A NEW repository, created Friday 18:00, named akayza.
    - Only the LIBRARIES in section 4 come across, in ONE labelled commit,
      listed in REUSE.md with their source.
    - NO product code is copied: no screens, services, feed logic,
      ranking, demand logic, matching or verification designs. Akayza's
      Order Book, Loan Book, ordering and Market are written fresh this
      weekend, to this plan, and they are deliberately simpler.
    - No shared database, no shared deployment, no shared accounts, no
      shared API.
    - The earlier product's name appears nowhere in the Akayza
      repository, including commit messages and comments.

Why this matters more than before: Akayza now has the same KIND of
tools (books, supplier ordering, a feed). Similar features are fine.
Copied code is not. It would blur what's ours from before and what's
jointly built at the event. See V1_13 R6.

6. BACKEND STACK
---------------------------------------------------------------------------

    Python 3.12+, Flask 3.1, Flask-SQLAlchemy 3.1 / SQLAlchemy 2.0,
    Alembic via Flask-Migrate, Flask-JWT-Extended, marshmallow 4,
    Flask-Limiter 4, psycopg2, PostgreSQL.
    NEW: cryptography (Ed25519 verify), hmac/hashlib (stdlib),
    Jinja2 for the one public checker page.

    STORAGE RULE (rev 4): never recompute a hash from a jsonb column.
    PostgreSQL's jsonb reorders keys and normalises numbers, so the
    stored JSON no longer matches what was signed. Keep the exact
    canonical bytes in a BYTEA column (payload_canonical); the jsonb
    copy is for queries only.

    THE CHECKER PAGE (rev 4) runs as its own small Flask process
    (checker.py) on its own port, with a read-only database user and
    ONE route, /s/<token>. The tunnel points at it, never at the API
    (V1_09 section 4). Share tokens are 128 random bits, stored only as
    SHA-256 hashes, so a database leak exposes no working link.

    Photos: stored on the API server's disk under /media for the demo,
    each file's SHA-256 sealed in the event. Cloud storage is roadmap.
